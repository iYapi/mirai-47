# PostgreSQL Database Pipeline

This document explains the dynamic database pipeline that connects the scraping engine to your remote PostgreSQL server.

---

## 1. Dynamic Connections
1. **Configuration**: Credentials (Host, Port, User, Password, DB Name) are set via the **Database Config** tab on the React frontend.
2. **Testing**: Clicking "Test Connection" sends a payload directly to the FastAPI `/api/postgres/test` endpoint, which checks TCP connection limits and authenticates with PostgreSQL using `psycopg2`.
3. **Saving**: Once verified, the credentials are saved into the SQLite singleton configuration row (`PostgresConfig` ID=1) and status is set to `connected`.

---

## 2. Automatic Table Migrations
When saving a working configuration, the backend instantly invokes `init_db()` to prepare the database schema. You do not need to perform manual tables migrations or run SQL queries.
It executes the following SQL statements to establish the table schema and search indexes:

```sql
CREATE TABLE IF NOT EXISTS raw_scrapes (
    id SERIAL PRIMARY KEY,
    url TEXT,
    timestamp TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    raw_data JSONB NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_products_url ON raw_scrapes(url);
CREATE INDEX IF NOT EXISTS idx_products_timestamp ON raw_scrapes(timestamp);
CREATE INDEX IF NOT EXISTS idx_products_source ON raw_scrapes ((raw_data->>'source'));
```

---

## 3. Product Insertions
Once a scraper completes execution:
1. The backend reads the temporary JSON data generated by the script.
2. It fetches the saved PostgreSQL credentials from SQLite.
3. If PostgreSQL is offline or unconfigured, the run writes the results into the local Pending Sync SQLite queue.
4. If online, the pipeline initializes `PostgresClient` and saves the cleaned URL, parsed ISO timestamp, and serializes the complete scraped object inside the `raw_data` JSONB column.
5. Injected database records are instantly queryable via the **Data Explorer** panel on the UI.

---

## 4. Querying and Sorting JSONB Fields
To retain backward-compatibility and database speed, database retrievals execute Postgres JSONB arrow operator casts. For example:
- **Filtering**: `WHERE raw_data->>'source' = %(source)s`
- **Sorting**: `ORDER BY (raw_data->>'original_price_cleaned')::bigint DESC NULLS LAST`
- **Selecting virtual fields**:
  ```sql
  SELECT 
      id,
      url,
      timestamp,
      raw_data->>'product_name' AS product_name,
      (raw_data->>'original_price_cleaned')::bigint AS original_price_cleaned,
      ...
  FROM raw_scrapes
  ```

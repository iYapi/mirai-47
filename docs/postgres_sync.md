# PostgreSQL Database Pipeline

This document explains the dynamic database pipeline that connects the scraping engine to your remote PostgreSQL server.

---

## 1. Dynamic Connections
Instead of using hardcoded server credentials in environment files, the database configuration is managed dynamically:
1. **Configuration**: Credentials (Host, Port, User, Password, DB Name) are set via the **Database Config** tab on the React frontend.
2. **Testing**: Clicking "Test Connection" sends a payload directly to the FastAPI `/api/postgres/test` endpoint, which checks TCP connection limits and authenticates with PostgreSQL using `psycopg2`.
3. **Saving**: Once verified, the credentials are saved into the SQLite singleton configuration row (`PostgresConfig` ID=1) and status is set to `connected`.

---

## 2. Automatic Table Migrations
When saving a working configuration, the backend instantly invokes `init_db()` to prepare the database schema. You do not need to perform manual tables migrations or run SQL queries.
It executes the following SQL statements to establish the table schema and search indexes:

```sql
CREATE TABLE IF NOT EXISTS scraped_products (
    id SERIAL PRIMARY KEY,
    product_name TEXT NOT NULL,
    original_price TEXT,
    original_price_cleaned BIGINT,
    discount_price TEXT,
    discount_price_cleaned BIGINT,
    discount_percentage TEXT,
    rating TEXT,
    rating_cleaned NUMERIC(3,2),
    sold_count TEXT,
    sold_count_cleaned INTEGER,
    store_name TEXT,
    store_location TEXT,
    store_type TEXT,
    source TEXT NOT NULL,
    page INTEGER,
    scraped_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_products_source ON scraped_products(source);
CREATE INDEX IF NOT EXISTS idx_products_scraped_at ON scraped_products(scraped_at);
```

---

## 3. Product Insertions
Once a scraper completes execution:
1. The backend reads the temporary JSON data generated by the script.
2. It fetches the saved PostgreSQL credentials from SQLite.
3. If PostgreSQL is offline or unconfigured, the run finishes with status `completed` but warns the user in the logs that data was not saved to database.
4. If online, the pipeline initializes `PostgresClient` and runs a bulk insert execution, converting date timestamps into timezone-aware PostgreSQL timestamp records.
5. Injected database records are instantly accessible via the **Data Explorer** panel on the UI.
